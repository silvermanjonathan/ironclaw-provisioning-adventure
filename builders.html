A Note for Builders

Where the right answers come from

This book is fiction, but its choices are not. Each of the nine decisions is a real IronClaw provisioning decision, and every safe answer is grounded in the IronClaw documentation — most as near-verbatim recommendations, three as documented principles the story dramatizes. Here is the honest map.

PageSafe choiceStatusDocumentation basis
2System keyringDocumentedOnboarding wizard, step 2: “System keyring is recommended; use an environment variable on servers/containers without a keyring.” The env-var option is the docs’ own fallback — which is why it tempts.
6Sandbox onDocumentedDocker sandboxing (wizard step 7): LLM-originated commands run with no credential access, limited filesystem reach, allowlisted network. “Can be disabled” is the pressure the story applies.
9Poll out, or one locked tunnelDocumentedPolling is the docs’ stated no-tunnel alternative; the gateway defaults to local-only (“recommended”); direct exposure is “generally not recommended”; public endpoints require auth and least privilege.
13Look-only, or a person presses the buttonAdaptedThe docs’ least-privilege principle applied to the processor-side key. IronClaw scopes where a secret may be sent; the read-only / prepare / unattended tiers are issued by the payment processor, not toggled in IronClaw.
18Trim the list to two websitesDocumentedTools declare allowed_hosts; anything else is rejected before the connection is made. “Review capabilities.json before installing any WASM tool from an untrusted source.”
22One case at a timeAdaptedWorkspace prefix scoping is the documented mechanism (“scopes which memory paths a component may touch”); the per-dispute workflow built on it is invented practice.
28Read the code first, or reduced powersDocumentedNearly verbatim: “A skill in a trusted directory has the same tool access you do. Never place a skill file there without reading it first.” Registry installs run attenuated, read-only — the broken demo is the documented fail-closed behavior.
32Set all three limitsAdaptedThe guardrails block is documented — rate limit, call and token caps, timeouts, plus “Always set rate_limit on webhook-triggered routines.” The currency-denominated spend cap is invented: it is the ceiling this domain needs, and no dollar field ships today.
37Tune the channelDocumentedReal-time leak detection, the safety layer, and logging are documented; the severity-tuning evening dramatizes that class of work rather than naming a feature.

Two more groundings: the “two manuals disagree” device is modeled on real, listed self-contradictions in the IronClaw docs — and every citation at the end of every ending is a real, public incident. What stays fiction is everything at Quillon: no IronClaw save or failure is depicted, because none is on the public record. Do not let a story — this one included — stand in for your own red-team.

The full mapping with source URLs lives in SOURCES.md. Docs drift; verify against the live pages before relying on wording. That is, after all, the book’s entire thesis.
